# 团队协作迁移验收清单

Web 负责团队执行调度，使用当前创建的 Agent、统一聊天列表、可变群成员和管理员保护。以下条目说明协作行为及验收范围。

- 管理员模式：所有用户消息先交管理员；管理员可串行委派或并行委派一批成员，整批终结后只复核一次。
- 成员成功、失败或中断均形成可复核结果；管理员复核不增加轮数。
- 自由模式：显式提及优先，无提及按自动参与配置接力；无关自动成员可静默退出，管理员必须公开答复。
- 默认 3 轮，支持 1～100 与 -1（不限）；只在自动接力边界执行上限判断。
- 运行中用户消息先持久化再排队；同一成员串行、每群最多 3 个执行、全局最多 4 个执行。
- 成员任务、批次与后续调度计划持久化；重启后核对已有执行，不重发未确认的提示词，也不重复复核。
- 上下文按照触发点截取，保留附件、失败结果和省略提示；不把后排用户请求串入先前任务。
- 支持整轮停止与单成员停止；审批、澄清、超时/断线与取消结果绑定具体成员任务。
- Web/iOS 保持原有聊天布局，用成员头像表现并发状态；恢复排队发送和不限轮数设置。

## 已完成的验证

`tests/server/workspace.test.ts` 覆盖管理员入口、串行依赖、并行批次、失败/中断回流、复核不占轮数、自由讨论静默退出、公开答复兜底、排队与上下文隔离、全局/群并发限制、不限轮数、并发审批、事务回滚、批次恢复、长历史分页核对、旧执行迁入与停止失败重试。

`tests/e2e/workspace-chat.spec.ts` 通过真实 Web 界面验证管理员先处理后委派，执行中发送的消息持久化排队，前一轮结束后自动处理后一条消息，并验证模板、成员管理和历史同步。

iOS 的 `testTeamWorkspaceStaysInsideOriginalDrawer` 验证原有页面结构、群内成员管理、模板分工、执行中发送并排队、完成后继续回复与不限轮数设置。成员并发头像状态另有 `WorkspaceChatTests` 回归。

验收使用独立标准 Hermes 协议测试服务，不修改生产用户聊天记录。实际远端模型和那台机器的部署状态需以其运行日志为准。
