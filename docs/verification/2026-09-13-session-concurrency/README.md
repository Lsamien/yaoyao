# Bot 独立会话并发验收

基线：主分支 `b880460`。开发分支：`codex/session-continuity-10`。

## 行为

- 同一机器人可以在不同聊天或话题中同时回复。顺序约束按既有会话绑定（聊天 ID、话题 ID、机器人 ID）判断。
- 全局最多执行 10 个 Bot 轮次，超出的已接收工作保留在队列中；运行中及状态待确认的工作继续占用额度。
- 同一群聊最多接收 10 个未完成话题，第 11 个新话题明确返回并发限制，不中断或丢弃已有工作。用户入口和团队工具使用相同限制。
- 同一话题内原有的成员协作限制（最多 3 个并行轮次）和主持人顺序继续生效。
- 停止、交互答复、历史恢复仍通过原绑定定位会话。虚拟机独占租约、浏览器和物理桌面的操作队列继续控制共享资源；虚拟机数量配置独立于 Bot 并发数。

## 验证

运行 `bash docs/verification/2026-09-13-session-concurrency/verify.sh`。

使用隔离临时数据库和本机 WebSocket 夹具，不调用真实模型或线上会话。覆盖：

1. 同一机器人 10 个话题同时进入执行，各自获得独立 session；第 11 个话题被拒绝且没有发送任何中断。
2. 同一机器人的不同话题交错完成，消息、上下文、存储会话和未读状态各自归属。
3. 同一 session 的追问排队并复用原会话；停止其中一个话题不会停止另一话题。
4. 同名审批请求隔离，答复只发给对应 session。
5. 两个并发 session 重启后各自核对历史，不重新提交用户请求。
6. 跨聊天达到全局 10 路后保留后续工作；完成后继续执行，单话题最多 3 路。
7. 共享浏览器操作串行执行，取消一个排队 session 不取消前后两个 session；虚拟机租约继续拒绝第二个占用者。

结果见 `results.txt`。本次没有修改部署、安装包或正式版本号。
