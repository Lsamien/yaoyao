# Bot 会话同步与统一文件传输设置验收

## 实现

- 启用 OpenViking 后，后台分页扫描全部保留消息（包含归档），同时消费 SQLite 持久事件。账号、Bot、会话、话题及服务地址/account 共同确定 session；服务重启或重新启用会再次复核历史。
- 同步用户正文、该 Bot 的完成/失败/中断回复、Bot 通信正文及附件元信息。排除临时助手、隐藏消息、独立/内联思考、工具记录和附件二进制。群聊按实际参与的 Bot 及话题隔离。
- 本地记录消息 ID、指纹和发送进度。每次追加前核对远端 messages.jsonl；远端已写入但回执丢失时，恢复后只追加缺失消息。出现顺序/内容冲突时停止追加并显示错误，不覆写远端。
- 失败退避重试，连续三次后等待管理员重试。停用暂停，删除会话/话题/Bot 清理对应 session；停用期间删除 Bot 的远端用户在重新启用后清理。不同服务/account 的进度独立保留，切回对应配置后继续处理。
- 禁用 session 原生记忆策略和继承的自动提交策略，不调用 commitSession；原有长期记忆提炼、编辑、遗忘及暂停设置不变。
- 「Bot 设置 → Bot 记忆」展示会话待同步、已完成、失败数量、最近错误及重试按钮。管理员 API：GET `/api/app/admin/openviking/session-sync`；POST `/api/app/admin/openviking/session-sync/retry`。
- 「Bot 设置 → 电脑」提供全局单文件上限，默认 25 MiB、整数 1–100 MiB，只有管理员可修改；旧客户端保存其他字段保留现值。
- `desktop_file_copy` 支持电脑名称/编号、`server` 和当前 Bot 的 `vm`。服务端在开始时锁定上限，512 KiB 分块复制，目标先暂存、核对长度与 SHA-256、再提交，默认不覆盖，保留源文件。每块检查授权、取消、连接代次和接管状态。提交回执丢失时查询结果，不重复提交。
- 桌面端、Runner 和 Hermes 工具桥声明分块能力；缺少 VM 能力时提示升级。旧桌面端仍可复制不超过配置值与旧 10 MiB 上限的文件。旧 `computer_copy_file` 也使用统一上限和分块协议，保留原工具的覆盖语义。聊天附件上传与导出维持独立限制。
- 失败执行尽力清理；桌面端撤销/回收会关闭暂存文件，Runner 释放同代次 VM 时清理本轮暂存，Hermes 撤销绑定时清理对应暂存。端点另有 10 分钟过期回收；进程强制退出后未能清理的磁盘暂存不承诺立即回收。

## 联调边界

OpenViking 测试使用协议替身，没有连接真实 OpenViking 服务。跨设备链路使用桌面/Runner 协议替身；VM 文件端点在本机真实 Python 子进程中执行，没有连接另一台物理电脑或真实 VM 做网络传输。因此真实 OpenViking 版本兼容性、跨机器网络中断、100 MiB 的实际网络耗时仍需部署后联调。
