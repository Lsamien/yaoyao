# Bot 模型设置验证

设置由 Bot 持有，`provider` 与 `model` 成对为空表示继承。`reasoningEffort`、`fastMode` 分别允许继承；`none` 表示关闭思考，速度保留 `normal / fast / auto / cold`。资料保存使用 `expectedRevision` 防止覆盖其他端的新版本；旧客户端没有提交 `modelSettings` 时保留原值。

Web／桌面端在 Bot 个人资料新增“模型设置”，iOS 和 Android 在资料编辑器中提供相同入口。保存不改变 Profile，也不打断当前轮次。各个会话、群聊、队列及定时任务共用的执行入口在下一轮获取 Bot 快照，检查模型、思考和速度的会话配置回执；运行检查记录保存资料版本、有效值及应用结果。

断线和重启恢复只追踪原轮次。恢复继承会覆盖已有会话的旧设置。原生模型费用确认绑定 Provider 与模型；长上下文切换产生的额外确认保存在 Bot 中，回到资料保存流程确认后才能重试。

## 验证结果

- 工具桥 Python 测试：33 项通过。涵盖模型目录、四种速度、关闭思考、Provider 路由、能力未知、配置错误、凭据隔离及安装兼容。
- 本机已安装 Hermes 只读检查：真实模型目录读取和默认配置解析成功，没有修改 Profile 或安装插件。
- Web 与服务端类型检查通过。
- 新增服务端、运行链路与 Vue 用例通过：同一 Bot 的旧单聊和两个群聊、同 Profile 的 Bot 隔离、正在回复时保存、排队下一轮、恢复继承、恢复不重发、原生配置失败不提交、费用确认、版本冲突、草稿保护、保存期间收到新版本、旧桥禁用编辑、切换基础 Profile 后重新加载。
- 相关完整测试套件有已存在的失败：`workspace.test.ts` 两项上下文百分比断言、`workspaceRoutes.test.ts` 一项已停用远端来源断言、`botProfileDialog.test.ts` 一项旧资料字段断言。已在修改前的 HEAD 副本中复现同样 4 项失败。
- iOS：编译、76 项 WorkspaceChat 单元测试及 1 项资料页 UI 测试通过。验证全部速度的协议和快照、明确空值、确认目标与版本、`agent.changed`、保存及重入回显、未保存草稿关闭保护。既有 250 ms 延迟用例曾出现计时失败，最终复跑通过。
- Android：编译、core:model／core:network 测试通过；2 项模拟器 UI 测试通过，覆盖保存和回显、未保存草稿保护、另一端保存后的草稿保留、禁用旧版本保存和重新加载。
