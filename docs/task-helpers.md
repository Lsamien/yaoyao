# 任务级临时助手

管理员可使用 `workspace_create_helper` 为已有团队目标创建一个临时隔离助手，并同时分派具体子任务。与持久 Agent 不同，临时助手没有独立单聊，不加入团队的永久成员列表，只参与创建它的目标和该目标当前的运行阶段。

## 生命周期与权限

- 创建时记录 `temporaryGoalId`、`helperActivation`、创建者、来源运行和原 Runner ID。调用身份由当前受权轮次提供，模型不能指定这些字段。
- 工具必须提供目标、名称和具体工作，可补充职责、验收要求和依赖。创建助手与子任务在同一个持久命令中完成，同一 requestId 重试不会重复创建。
- 每个目标最多 8 个有效临时助手、累计最多 32 个；执行仍受 Agent 串行约束和节点电脑配额限制。
- 助手固定使用隔离电脑，不获得组队权限，不能变成持久成员、加入其他群聊、切换执行方式或执行其他任务。
- 用户恢复目标时会产生新阶段。旧阶段的临时助手不恢复；需要继续工作时创建新助手或由管理员调整负责人。
- 只有声明 `helper-retirement-v1` 的 Runner 才会向管理员提供创建助手工具，避免在不能清理的旧执行节点上创建临时资源。

## 退役与清理

目标完成、受阻、取消、删除，或进入新运行阶段后，旧助手退役。先撤销执行资格，再停止所属运行；不能确认停止时保留待清理状态，不把工作区交给其他任务。

清理状态保存在助手记录中，服务重启后继续检查。离线节点或失败的清理会重试，界面显示“已退役，等待清理”。清理只发往原 Runner；更换节点不会把清理请求发送到另一台电脑。

Runner 在删除资源前保存退役记录和原配置，核对环境归属，停止相关模型进程、释放电脑、移除工作目录和临时模型会话。退役标记保留，迟到请求不能重新创建该电脑。已导出的文件保存在控制面，原作者和任务来源不变，不随工作区删除。

## 跨端表现

Web、iOS 和 Android 的任务进度显示“临时助手”及退役状态。持久团队的成员选择器排除这些助手；后端同时执行任务边界验证，旧客户端或手工请求也不能绕过。

## 验收

- 服务测试覆盖创建去重、跨任务拒绝、禁止提权和转成持久成员、取消后退役、异步清理，以及清理中断后的重试。
- 真实 Docker / Hermes Worker 验收：管理员创建临时助手，助手完成隔离工作并导出文件；目标结束后工作目录被删除，已回传产物保留。
- 模型服务在该验收中使用确定的测试响应，没有使用付费模型；它证明执行协议和生命周期，不代表任意任务的自主决策质量。
- 移动端校验任务身份解码、状态文案和成员选择过滤；完整电脑面板与人工接管仍属于后续交付范围。
